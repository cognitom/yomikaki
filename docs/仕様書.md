# 読書タイピング「yomikaki」 仕様書

小説を読みながら、かな入力＋漢字変換を実践的に練習するための特殊テキストエディタ。

> 本書はフェーズ1（エディタ核）の実装完了時点で、実機検証の結果を反映して改訂したもの。

---

## 1. 目的と前提

- ローマ字入力ではなく **かな入力** の練習。ただしブラウザから入力方式は判別できないため、後述の「打鍵効率」で間接的に評価する。
- 変換を含めた実践的な練習。**どこで区切って変換するかはユーザーの自由**（入力すべき文字数は可変長）。
- 文章のソースは青空文庫の新字新仮名作品。
- 成果物はアーティファクト、最終的には GitHub Pages に置ける単体 HTML。

---

## 2. 画面構成

```
┌────────────────────────────────────────┐
│ 作品名 / 著者     速度 打鍵 効率 変換 誤り │ ← ヘッダ（統計）
├────────────────────────────────────────┤
│                                        │
│        ┌──────────────────┐            │
│        │ 吾輩は猫である。   │            │ ← 入力欄（中央寄せ・下端固定・上へ伸びる）
│        │ 名前はまだ無い。   │            │
│        └──────────────────┘            │ ← ギャップ（可変・変換候補窓の逃げ）
├────────────────────────────────────────┤
│ …│つ│か│ぬ│。│何│で│も│薄│暗│い│…  │ ← お手本テープ（全幅 fixed・横スライド）
└────────────────────────────────────────┘
```

### 入力欄
- `contenteditable` な div。自由なエディタではなく、**IME の受け皿とキャレット位置の提供に用途を限定**する。
- 打ったものは全て残る。削除・改行・貼り付け・カーソル移動はすべて禁止。
- 正誤のフィードバックが文字単位で付く。
- 行の折り返しはブラウザの自然な折り返しに任せる（事前の行分割・禁則処理は行わない）。
- **幅は `min(80vw, 全角30字)` で中央寄せ。** テープは全幅のままなので、入力欄の外側の余白がそのまま先読み領域になる。
- 溢れたら自動的に上へ伸びる。常に最下段が見えるようスクロール位置を追従。

### お手本テープ
- 画面最下部に fixed。1列のテープが横方向に伸び、画面幅で見切れる。
- 原稿用紙のマス目状のセル。1トークン1セル。
- **原則としてキャレットに横位置を合わせる。** 正しく入力する限り行ごとにスライドし、誤入力があれば文字単位で横にズレる。
- ただし**先読みが7文字ぶん見えなくなる場合は、その分だけ左へ押し戻す**（後述）。
- 朱のマーカーは**テープ上の現在位置のセル**に付く。押し戻しが働くとキャレットとは離れる。
- ルビはセルの上に絶対配置で浮かせ、字送りに影響させない。
- 入力対象外のセル（改行 `¶`、行頭の全角スペース）は緑の薄色にし、打つ必要がないことを示す。
- 半角スペースは入力対象なので、空のマスとして残る（罫線だけが見える）。判別できるよう `word-spacing` で全角の半分の幅に広げてある。

### 字送りの一致
入力欄とテープは**同じフォント・同じフォントサイズ・letter-spacing は両方 normal** でなければならない。行内での字送りがずれるとテープが1文字ごとに揺れる。

**英数字は全角幅に揃えず、可変幅のまま描く。** 原稿用紙のマス目からは逸脱するが、全角に引き伸ばした英文は見た目の違和感が強い。入力欄とテープが同じフォント・同じサイズで描くかぎり、可変幅でも字送りは一致する。1マス固定にしてよいのは、入力欄に対応する文字を持たない改行記号 `¶` だけ（`<br>` は幅を持たないので、テープ側の幅は自由に決められる）。

**カーニングは両方で切る。** テープは1セル＝1文字の `inline-block` なのでペアカーニングが効かない。入力欄だけ `AV` / `To` のようなペアが詰まると、その差の分ずつテープが左へ流れる（実測で英単語2つ・15字ぶんで 12.5px）。`font-kerning:none` と `font-variant-ligatures:none` を入力欄とテープの両方に指定する。

**半角スペースは `word-spacing` で広げる。** 素の半角スペースは全角の 25% しかなく、テープ上で空のマスとして判別しにくい。`--wordsp:.25em` を掛けて全角の 50% にする。ただし**入力欄・テープ・実測用プローブ（`.probe`）のすべてに同じ値を掛けること。** 入力欄とテープでずれれば字送りが崩れ、プローブだけ外れると `estW` の推定値が実際と食い違う。

**半角スペースを潰してはならない。** 入力欄が `white-space:normal` のままだと行末の空白が消えて `caretX` が進まず、テープのセル（inline-block）でも空白が消えて幅が 0 になる。入力欄は `pre-wrap`、セルは `pre` にする。

## 3. データモデル

青空文庫テキストをパースしてトークン列を作る。

```js
token = { ch, ruby, rubySpan, typable }
```

- `typable: true`  … 入力対象。連結したものが照合用の `target` 文字列。
- `typable: false` … 改行、行頭の全角スペース、および[入力スキップの対象](#入力スキップの対象)。入力対象外で、通過時にアプリが自動挿入する。

補助構造:

| 名前 | 内容 |
|---|---|
| `target` | 入力対象文字列（表示・字送り用。原文のまま） |
| `targetKey` | `target` の[類似記号を寄せた](#類似記号の統一)照合用の写し。長さは `target` と一致する |
| `tokenOfTarget[t]` | target インデックス → トークンインデックス |
| `pre[t]` | target 文字 `t` の直前に自動挿入する非入力文字列（`"\n　"` など） |

末尾に番兵トークン（`了`）を置き、`cursor === target.length` のときの参照先とする。

### 半角／全角の統一

お手本の英数字は半角に統一する。入力が全角でも半角に変換してから照合するので、どちらで打っても正誤判定は変わらない。お手本と入力は同じ `toHalf()` を通す。

| 文字 | 扱い |
|---|---|
| 全角の英字・数字・記号（U+FF01–FF5E） | 半角へ寄せる |
| 全角スペース（U+3000） | そのまま。行頭のものは従来どおり自動入力 |
| 半角スペース | そのまま。**自動入力にはしない** |

半角スペースを自動入力にしないのは、英文中の空白まで勝手に入ると打鍵のペースが崩れるため。手で打つ対象として残す。

**正規化は記法パーサより後でなければならない。** ルビ区切りの `｜`(U+FF5C) と注記の `＃`(U+FF03) は全角英数記号の範囲に入るので、原文全体に先に掛けると記法そのものが壊れる。トークン化のときに一文字ずつ掛ける。

### 類似記号の統一

字形が近く、読んでいる字の大きさでは区別のつかない記号がある。IME も「まる」と打てば `〇` `○` `◯` を並べて出すので、原文がどれなのかは打つ側には分からない。これらは代表字に寄せてから照合する。

**半角化と違って表示は変えない。** `〇`（数字のゼロ）と `○`（伏字）の書き分けは原文の情報であって、こちらで潰してよいものではない。寄せるのは判定用のキーだけで、テープにも入力欄にも原文・打った字がそのまま残る。

| | 表示 | 照合 |
|---|---|---|
| 半角／全角の統一 | 寄せる（`ＡＢＣ` → `ABC`） | 寄せた字で |
| 類似記号の統一 | **寄せない**（`〇` は `〇` のまま） | 寄せた字で |

```
target    … 原文のまま。テープ・入力欄・字送りはこちらを見る
targetKey … unifyAll(target)。DP の照合窓 Mloc はこちらから切り出す
typed[].ch  … 打った字そのまま（入力欄に残る）
typed[].key … unify(ch)。正誤の比較はこちらどうしで行う
```

`SIMILAR_GROUPS` は `[代表字, 寄せる字…]` の並び。行を足せば増やせる。最初から完全である必要はない。

| 代表字 | 寄せる字 | 備考 |
|---|---|---|
| `―` | `‒–—─━` | 長音符 `ー`(U+30FC) は**絶対に入れない**。「コーヒー」が打てなくなる |
| `-` | `‐‑−﹣` | ハイフン・マイナス |
| `…` | `⋯‥` | 二点リーダも点を数えないと見分けられない |
| `○` | `〇◯◦∘` | マル |
| `・` | `･·•` | 中黒 |
| `~` | `〜∼` | 全角チルダ `～` は半角化で既に `~` になっている |
| `'` | `‘’‛′` | アポストロフィ |
| `"` | `“”‟″` | 引用符 |

制約が2つある。

- **1文字→1文字に限る。** `target` と `targetKey` の長さがずれると `cursor` が別の字を指す。
- **寄せ先を2段にしない。** ある組の代表字が別の組の変換対象になっていると、寄せ結果が表の並び順に依存する。

### 青空文庫記法の処理
- `｜漢字《ルビ》` / `漢字《ルビ》`（`｜` 省略時は直前の漢字・カタカナ連続をルビ対象と判定）
- `［＃…］` 注記は除去
- ヘッダ（冒頭の凡例ブロック）と `底本：` 以降を削除
- `※［＃…、U+XXXX］` 外字は Unicode 併記があれば置換

### 入力スキップの対象

本文には「読んで進みたいが打ちたくないもの」（章見出し、場面転換の飾り、打ちようのない記号）と、「そもそも本文でないもの」（挿絵の代替テキスト、変換できなかった外字）が混じる。前者は自動入力にして本文には残し、後者は原文から落とす。

3つのリストで表す。増やすときはリストに1行足すだけでよい。

| リスト | 単位 | 扱い | 例 |
|---|---|---|---|
| `NOISE_LINES` | 行 | 行ごと削除。テープにも入力欄にも出ない | `挿絵1` / `〓` |
| `AUTO_LINES` | 行 | 行全体を自動入力。テープには薄く残る | `第一章` / `三` / `幕間` / `＊＊＊` |
| `AUTO_CHARS` | 文字 | その文字だけ自動入力。文中に現れても効く | `‡` `†` `※` `〓` |

リストは完全である必要はない。取りこぼしは「打つ対象として残る」だけで、誤って本文を消す方向には転ばない。**迷ったら `NOISE_LINES` ではなく `AUTO_LINES` に入れる。**

見出しの副題は空白で区切られたものだけを拾う（`第2章　出発`）。区切りなしまで許すと `第一部が完成した。` のような本文が見出しに化ける。

実装上の制約が2つある。

- **注記 `［＃…］` を除いた後に掛ける。** 行に注記が残っていると行全体の照合が効かず、見出しを拾えない。
- **`applySkips()` が返す `auto[]` は整形後テキストの添字。** ノイズ行を抜いたぶん位置がずれるので、`src` を戻り値の `text` に差し替えてからトークン化する。

## 4. 現在位置の定義（自己回復型）

打った文字列全体を T、お手本を M とする。

```
D[j] = editDistance(T, M[0..j))
cursor = argmax { j | D[j] が最小 }
```

同点のとき最も右の `j` を採る。これにより「打ち漏らしを認めて先へ進む」解釈が選ばれる。

| 誤り方 | キャレット | cursor | テープ |
|---|---|---|---|
| 置換（打ち間違い） | +1 | +1 | 動かない |
| 挿入（余計に打った） | +1 | 0 | 1文字ぶん右へズレる |
| 脱落（打ち漏らし） | 0 | +1 | 1文字ぶん左へズレる |

### 計算量の抑制

- **帯状 DP**: アンカーからの窓（96文字）に限定した1行 DP を1文字ずつ更新。O(W)/文字。
- **アンカー**: 直近8文字が連続一致した時点で確定させ、それ以前の T と M を切り捨てて DP をリセット。
- **強制アンカー**: アンカーからの入力が 240 文字を超えたら安全弁として強制確定。

### 正誤の分類
DP 行列を逆走して各入力文字を分類する（`ok` = 一致 / `ng` = 置換または挿入）。アンカーより手前は判定を凍結し、再描画しない（色のチラつき防止）。

### 検証状況
判定エンジンと描画は Node 上で以下を確認済み。
- 完全一致・置換・挿入・脱落の各ケースで `cursor` が期待値どおり
- 10文字の無関係な文字列を打ち込んでも自己回復する
- 誤入力率35%で1〜6文字のランダム変換単位を120通り流し、改行と全角スペースの自動挿入位置が常に正しい
- 全角で打った英数字が半角のお手本と一致し、入力欄にも半角で残る
- 章見出し・打ちようのない記号を打たずに先へ進め、自動入力として本文に残る。挿絵行はテープからも消える
- 字形の近い記号（`―`／`—`、`…`／`⋯`、`○`／`〇` など）はどちらで打っても一致し、表示は打った字のまま残る

## 5. IME の扱い

### DOM 構造

```html
<div class="editor" contenteditable="true">
  <span class="frozen"  contenteditable="false">…確定済み（凍結）…</span>
  <span class="live"    contenteditable="false">…確定済み（再評価対象）…
    <span class="anchor"></span>            <!-- 幅0・キャレット位置の測定用 -->
  </span>
  <span class="compose">&#8203;</span>       <!-- キャレットの受け皿。常に ZWSP を保持 -->
</div>
```

確定済みを `contenteditable="false"` にすることでキャレットが過去に入り込めない。同一ブロックフロー内なので **変換候補ウィンドウが正しい位置に出る**（隠し textarea 方式にしなかった最大の理由）。

### 3つの鉄則（すべて実機バグから導出）

**① `composeEl` を空にしてはならない。**
空になるとブラウザが有効なキャレット位置を失い、要素が編集可能とみなされなくなって **IME がデタッチする**。ゼロ幅スペース（U+200B）を常駐させる。確定文字列・直接入力からは ZWSP を除去する。

**② 変換に関わる `inputType` を絶対にブロックしない。**
IME は変換中に `deleteCompositionText` → `insertCompositionText` を発行する。前者を `preventDefault` すると変換が壊れる。`inputType` に `Composition` を含むものは無条件に通す。

**③ 確定処理を `setTimeout` で遅延させてはならない。**
`compositionend` の 1ms 後に次の変換が始まりうる（Enter を押さずに次の文を打ち始める操作は自然に起きる）。`setTimeout(0)` は次のタスクなのでキー入力に追い越され、`clearPending()` が新しい未確定文字列を破壊する。**`queueMicrotask` を使う**と現在のタスク直後＝次のキーイベントより確実に前に走る。

### イベント

| イベント | 処理 |
|---|---|
| `compositionstart` | 変換中フラグ。テープの更新を停止 |
| `compositionupdate` | スクロールのみ追従（DOM は触らない） |
| `compositionend` | `event.data` から ZWSP を除いて確定文字列とし、`queueMicrotask` で確定処理 |
| `input` | `isComposing === false` かつ確定直後 80ms のガード外のときだけ直接入力として処理 |
| `beforeinput` | `Composition` を含む inputType は通す。それ以外の `delete*` / `insertParagraph` / `insertLineBreak` / `insertFrom*` / `history*` / `format*` を `preventDefault` |
| `keydown` | 打鍵カウント。加えてキャレットが `composeEl` の外にあれば、キー処理前に引き戻す |
| `selectionchange` | キャレットが `composeEl` の外なら押し戻す |

### キャレット復帰の3層構造
1. **原因の除去** … ZWSP 常駐
2. **キー処理前の復帰** … `keydown` 時に検査
3. **最終防衛線** … 500ms 間隔で検査し自動復帰（発動時はログに `heal` を残す）

### 変換中の制約
- DOM を触らない
- キャレットを動かさない（`placeCaret` は `composing` でガード）
- テープの `translateX` を更新しない（未確定文字列でキャレットだけが右へ動くため）

## 6. テープの位置合わせ

フォント幅を一切仮定せず、**実測座標から絶対値として毎回算出**する。

```js
tx   = caretX - leftInTape(cell[cursor])              // 原則：キャレットに揃える
over = (caretX + 先読み7字の幅) - (テープ幅 - 余白)
if (over > 0) tx -= over                              // 先読み確保のため押し戻す
markerX = tx + leftInTape(cell[cursor])
```

- `caretX` … `live` 内のアンカー要素の X 座標（テープ表示域の左端が原点）
- `leftInTape()` … `offsetParent` を辿って `.tape` 基準の左端を求める。`transform` の影響を受けない

行の途中ではキャレットとテープセルが同じ幅ずつ進むため差分ゼロ＝**テープ静止**。折り返しでキャレットが左端へ戻った瞬間に1行ぶん左へ**スライド**する。`transition: transform 180ms ease-out`。

押し戻しが効いている間は、`caretX` の増加とともに `over` も増えるため、**現在位置のセルが右端付近に固定されたままテープだけが1文字ずつ流れる**タイプライタ的な挙動になる。折り返しで `over` が負に転じ、通常のキャレット追従へ戻る。

押し戻しの発動条件（`LOOKAHEAD = 7`）:

| 画面幅 | 入力欄 | 右余白 | 押し戻し |
|---|---|---|---|
| 1280px | 30字 | 14.6字 | なし |
| 834px | 30字 | 4.3字 | 74px |
| 412px | 18.7字 | 2.3字 | 98px |

## 7. テープの仮想化

長編でも DOM 量を一定に保つ。

```html
<div class="tape">
  <i class="sp" style="width:4820px"></i>   <!-- 左スペーサ -->
  <span class="cell">吾</span> …            <!-- 窓（前後400トークン） -->
  <i class="sp" style="width:9000px"></i>   <!-- 右スペーサ -->
</div>
```

**左スペーサが要**。窓の開始位置ぶんを実際に押し出しておくことで、`offsetLeft` は常に「テープ全体の先頭からの距離」を返す。窓を差し替えてもスペーサ幅が同じだけ増減するため、描画中セルの `offsetLeft` は不変 ⇒ **飛びが原理的に発生しない**。`transition` を掛けたままで問題ない。

- 窓サイズ: cursor 前後 400 トークン
- 再構築の閾値: cursor が窓端から 150 トークン以内（ヒステリシス）
- タイミング: `requestAnimationFrame` 内で、translateX 更新より **先に** 実行
- スペーサ幅: 窓構築時に実測した各セル幅の累積和。未描画部分は文字種別の推定値（`estW`）
- 英数字は可変幅なので、`estW` の推定値はあくまで概算。ただし画面上の位置は**窓内の実測差分だけ**で決まり（`tx = caretX - leftInTape()` と `leftInTape()` に同じ誤差が乗って打ち消される）、スペーサの誤差は位置合わせに影響しない。ずれるのはテープの総延長だけ
- 半角スペースと `¶` は幅を実測する。フォント依存の値を決め打ちしない

## 8. 統計

| 指標 | 定義 |
|---|---|
| 打鍵数 | `keydown` のうち純粋な修飾キーを除いたもの。キーリピート（`e.repeat`）は数えない |
| 確定文字数 | `cursor` |
| 速度 CPM / KPM | 上記 ÷ 経過分（初回打鍵から計測、10秒以上の無操作は除外） |
| **打鍵効率** | 打鍵数 ÷ 確定文字数 |
| **平均変換長** | 総入力文字数 ÷ 確定回数 |
| ミス率 | `ng` 文字数 ÷ 総入力文字数 |

### 打鍵カウントの実際（実機検証で判明）

- **IME 経由のキーは `key` が Android で `"Unidentified"`、Windows で `"Process"` になる。** これらは実打鍵なので必ず数える。除外するのは `Control` / `Alt` / `Meta` / `CapsLock` / `AltGraph` / `ContextMenu` のみ。
- **Shift は打鍵に含める。** かな入力では小書き文字・記号・括弧に Shift が要るため、除外すると効率が実態より良く出る。
- **「変換操作打鍵（Space / Enter / 矢印）の内訳」は取得不可能。** `key` が `Process` / `Unidentified` に潰れるため区別できない。当初仕様から削除した。
- 代替として **平均変換長（字/変換）** を追加。変換単位が長すぎると誤変換時のやり直しが重くなるため、実践的には5〜10字が目安。

### 実測例
かな入力・外付けキーボードで「吾輩は猫である。名前はまだ無い。」（16字）を1回の変換で確定した場合:

```
打鍵29（かな23・Shift 4・変換 2） → 効率 1.81 / 字・変換 16.0
```

濁点が独立キーのため理論値 1.0 より高く出るのは正常。ローマ字入力なら同じ文で 2.3 前後になるため、判別指標として機能する。

## 9. テキスト取得（フェーズ2）

- 本体リポジトリ `aozorabunko/aozorabunko` を `raw.githubusercontent.com` 経由で取得する（CORS 可）。
- カードページ → 本文ファイルへのリンクを解析 → 本文を取得、の2段構え。作品IDから本文ファイル名を直接導出できないため。
- ファイルは Shift_JIS ⇒ `fetch` → `arrayBuffer()` → `new TextDecoder('shift_jis').decode()`
- カードページの「文字遣い種別」を読み、新字新仮名でなければ警告する。
- ネットワークが使えない環境（サンドボックス等）に備え、テキスト直接貼り付けの経路を必ず用意する。

## 13. PWA（ホーム画面へのインストール）

単一 HTML の原則は崩さない。`index.html` は `file://` でも単体で動いたまま、PWA に必要な最小限のファイルだけを外に置く。

```
manifest.webmanifest   名前・アイコン・standalone 表示
sw.js                  アプリシェルの先読み
icons/                 192 / 512 / maskable 512 / apple-touch 180
```

- **パスはすべて相対で書く。** GitHub Pages ではサブパス（`/yomikaki/`）配下に置かれるため、絶対パスを一つ混ぜるだけで scope もインストールも壊れる。`test/pwa.test.mjs` が機械的に検査する。
- **Service Worker は同一オリジンの GET しか触らない。** 青空文庫の取得（`raw.githubusercontent.com`）に介入すると CORS と Shift_JIS デコードの経路を壊しかねないので素通しする。
- HTML は network-first（更新が即座に届く）、アイコン等は cache-first。キャッシュ名にバージョンを持たせ、`activate` で古い世代を消す。
- オフラインでも起動でき、収録サンプルは打てる。本文の取得だけは通信が要る。
- `file://` では Service Worker を登録しない（そもそも登録できない）。

### 表示領域（standalone）

ホーム画面から起動するとブラウザ UI が消え、ヘッダとテープがノッチ／ホームインジケータと重なる。`viewport-fit=cover` を指定し、`env(safe-area-inset-*)` を CSS 変数 `--safeT/B/L/R` に受けて、ヘッダの上端パディング、テープの高さ、入力欄の下端、テープキャレットの `bottom` に加算する。

字送りの計算（`leftInTape` / `caretX`）は実測ベースなので、この加算の影響を受けない。

### インストール導線

- Chromium 系 — `beforeinstallprompt` を捕まえてヘッダに「ホーム画面へ」を出し、クリックで `prompt()`。
- iOS Safari — `beforeinstallprompt` がない。`"standalone" in navigator` で判別し、同じボタンから「共有 →ホーム画面に追加」を案内する。
