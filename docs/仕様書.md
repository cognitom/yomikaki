# 読書タイピング「yomikaki」 仕様書

小説を読みながら、かな入力＋漢字変換を実践的に練習するための特殊テキストエディタ。

本書は設計の全体像と「なぜそう決めたか」を持つ。実装の各論は以下に分ける。

- [テープ.md](テープ.md) — お手本テープの余白・字送り・位置合わせ・仮想化
- [IME.md](IME.md) — contenteditable と IME 捕捉、診断ログ
- [PWA.md](PWA.md) — ホーム画面インストールと Service Worker

---

## 1. 目的と前提

- ローマ字入力ではなく **かな入力** の練習。ただしブラウザから入力方式は判別できないため、「打鍵効率」で間接的に評価する。
- 変換を含めた実践的な練習。**どこで区切って変換するかはユーザーの自由**（入力すべき文字数は可変長）。
- 文章のソースは青空文庫の新字新仮名作品。
- 成果物は GitHub Pages に置ける単体 HTML。ビルドなし・依存なし。

## 2. 画面構成

```
┌────────────────────────────────────────┐
│ 作品名 / 著者     速度 打鍵 効率 変換 誤り │ ← ヘッダ（統計）
├────────────────────────────────────────┤
│        ┌──────────────────┐            │
│        │ 吾輩は猫である。   │            │ ← 入力欄（中央寄せ・下端固定・上へ伸びる）
│        │ 名前はまだ無い。   │            │
│        └──────────────────┘            │ ← ギャップ（変換候補窓の逃げ）
├────────────────────────────────────────┤
│ …│つ│か│ぬ│。│何│で│も│薄│暗│い│…  │ ← お手本テープ（全幅 fixed・横スライド）
└────────────────────────────────────────┘
```

- **入力欄** — `contenteditable` な div。自由なエディタではなく、IME の受け皿とキャレット位置の提供に用途を限定する。打ったものは全て残り、削除・改行・貼り付け・カーソル移動は禁止。正誤が文字単位で色付く。幅は `min(80vw, 全角30字)` で中央寄せ、溢れたら上へ伸びる。
- **お手本テープ** — 画面最下部。原稿用紙のマス目状に1トークン1セル。原則キャレットに横位置を合わせてスライドし、先読みが7文字を切るときだけ左へ押し戻す。入力対象外のセル（改行 `¶`・全角スペース・自動入力）は薄緑で「打たなくてよい」ことを示す。

描画の詳細（余白の導出、字送り一致の条件、押し戻し、仮想化）は [テープ.md](テープ.md)。

## 3. データモデル

青空文庫テキストをパースしてトークン列を作る。

```js
token = { ch, ruby, rubySpan, typable }
```

- `typable: true` … 入力対象。連結したものが照合用の `target` 文字列。
- `typable: false` … 改行・行頭の字下げ・スキップ対象。通過時にアプリが自動挿入する。

| 名前 | 内容 |
|---|---|
| `target` | 入力対象文字列。原文のまま（表示・字送り用） |
| `targetKey` | `target` の類似記号を寄せた照合用の写し。長さは `target` と一致 |
| `tokenOfTarget[t]` | target インデックス → トークンインデックス |
| `pre[t]` | target 文字 `t` の直前に自動挿入する非入力文字列 |

末尾に番兵トークン（`了`）を置き、`cursor === target.length` のときの参照先とする。

### 文字の正規化は2層

| | 表示 | 照合 |
|---|---|---|
| 半角／全角の統一 | 寄せる（`ＡＢＣ` → `ABC`） | 寄せた字で |
| 類似記号の統一 | **寄せない**（`〇` は `〇` のまま） | 寄せた字で |

- **半角化** — お手本の英数字は半角に統一し、入力も同じ `toHalf()` を通す。どちらで打っても判定は同じ。全角スペース（U+3000）は対象外（自動入力の対象なので、半角に寄せると境界が壊れる）。半角スペースは自動入力にせず、手で打つ対象として残す。
- **類似記号** — `―`／`—`、`○`／`〇` のように読みの字の大きさでは区別できない記号は、照合キーだけ代表字に寄せる。表示まで寄せると原文の書き分け（`〇`=ゼロ / `○`=伏字）が消えるため。括弧 `『【〈《` → `「`、`』】〉》` → `」` も同じ扱いにする。字形は似ていないが、和文では `「」` の代替として使われるもので、打ち分けは変換候補を選び直す操作にしかならない。対応表 `SIMILAR_GROUPS` と制約（1文字→1文字、寄せ先を2段にしない、長音符 `ー` を含めない）はコード内に記載。

正規化を記法パーサより後に掛ける等の壊れやすい規則は `test/invariants.test.mjs` が機械的に検査する。

### 青空文庫記法の処理

- `｜漢字《ルビ》` / `漢字《ルビ》`（`｜` 省略時は直前の漢字・カタカナ連続をルビ対象と判定）
- `［＃…］` 注記は除去。ヘッダと `底本：` 以降を削除。外字 `※［＃…、U+XXXX］` は Unicode 併記があれば置換

### 入力スキップ

「読んで進みたいが打ちたくないもの」（章見出し・飾り記号）は自動入力にして本文に残し、「本文でないもの」（挿絵の代替テキスト等）は原文から落とす。`NOISE_LINES`（行削除）/ `AUTO_LINES`（行を自動入力）/ `AUTO_CHARS`（文字を自動入力）の3リストで表し、増やすときは1行足すだけ。

リストは完全である必要はない。取りこぼしは「打つ対象として残る」だけで、本文を消す方向には転ばない。**迷ったら `NOISE_LINES` ではなく `AUTO_LINES` に入れる。**

改行と全角スペースはリストではなくトークン化の条件式で落とす。どちらも組版の空白であって、行頭の字下げも見出しの `上　先生と私` のような区切りも扱いは変わらない。

## 4. 現在位置の定義（自己回復型）

打った文字列全体を T、お手本を M とする。

```
D[j] = editDistance(T, M[0..j))
cursor = argmax { j | D[j] が最小 }
```

同点のとき最も右の `j` を採る。「打ち漏らしを認めて先へ進む」解釈が選ばれ、どんな誤入力からも自己回復する。

| 誤り方 | キャレット | cursor | テープ |
|---|---|---|---|
| 置換（打ち間違い） | +1 | +1 | 動かない |
| 挿入（余計に打った） | +1 | 0 | 1文字ぶん右へズレる |
| 脱落（打ち漏らし） | 0 | +1 | 1文字ぶん左へズレる |

計算量は3つの仕組みで抑える。

- **帯状 DP** — アンカーからの窓（96文字）に限定した1行 DP を1文字ずつ更新
- **アンカー** — 直近8文字が連続一致したら確定し、それ以前を切り捨てて DP をリセット
- **強制アンカー** — アンカーから240文字を超えたら安全弁として強制確定

正誤の分類は DP 行列の逆走で行う（`ok` = 一致 / `ng` = 置換・挿入）。アンカーより手前は判定を凍結し再描画しない（チラつき防止）。

## 5. IME の扱い

`contenteditable` を採用したのは、確定済みテキストと同一ブロックフロー内にキャレットが居ることで**変換候補ウィンドウが正しい位置に出る**ため（隠し textarea 方式にしなかった最大の理由）。

実機バグから導出した3つの鉄則がある。詳細は [IME.md](IME.md)、機械検査は `test/invariants.test.mjs`。

1. キャレットの受け皿 `composeEl` を空にしない（ZWSP 常駐。空だと IME がデタッチする）
2. `Composition` を含む `inputType` をブロックしない（変換が壊れる）
3. 確定処理は `setTimeout` でなく `queueMicrotask`（次のキー入力に追い越されない）

## 6. 統計

| 指標 | 定義 |
|---|---|
| 打鍵数 | `keydown` のうち純粋な修飾キーを除いたもの。キーリピートは数えない |
| 確定文字数 | `cursor` |
| 速度 CPM / KPM | 上記 ÷ 経過分（初回打鍵から。10秒以上の無操作は除外） |
| **打鍵効率** | 打鍵数 ÷ 確定文字数。かな入力かどうかの判別指標 |
| **平均変換長** | 総入力文字数 ÷ 確定回数 |
| ミス率 | `ng` 文字数 ÷ 総入力文字数 |

IME 経由のキーは `key` が `"Process"` / `"Unidentified"` に潰れるため**必ず数える**（実打鍵）。同じ理由で「変換操作打鍵の内訳」は取得不可能であり、当初仕様から削除して平均変換長で代替した。Shift はかな入力で実際に使うため打鍵に含める。

## 7. テキスト取得

- 本体リポジトリ `aozorabunko/aozorabunko` を `raw.githubusercontent.com` 経由で取得（CORS 可）。
- カードページ → 本文ファイルへのリンク解析 → 本文取得、の2段構え（作品IDから本文ファイル名を導出できないため）。
- 本文は Shift_JIS。`fetch` → `arrayBuffer()` → `TextDecoder('shift_jis')`。
- カードページの「文字遣い種別」が新字新仮名でなければ警告する。
- 通信が使えない環境に備え、テキスト直接貼り付けの経路を必ず用意する。

## 8. モジュール構成

```
aozora/   fetch + Shift_JIS 変換 + 記法パーサ → トークン列
engine/   帯状DP・cursor・分類・アンカー（純粋関数、UI非依存）
tape/     窓の仮想化・幅実測・translateX
editor/   contenteditable 制御・IME捕捉・描画
stats/    打鍵と時間の集計
storage/  しおり・記録
```

`engine` を純粋関数にしておくと判定ロジック単体でテストできる。実際、エディタ核の実装で出たバグはすべて UI 側（IME・DOM）に集中し、`engine` は無傷だった。

## 付記: この仕様書の書き方

- 本書には「何を・なぜそう決めたか」だけを書く。「どう実装したか」はコードとコメントに任せ、具体的な値や対応表はコード内のものを正とする。
- 特定部分の実装にしか関係しない詳細は `docs/` の各論（テープ.md / IME.md / PWA.md）へ分ける。本書からリンクする。
- 「守らないと壊れる」規則は `test/invariants.test.mjs` に機械検査として写し、本書側は要点と理由を1〜2行に留める。
- 検証済み・未検証の事実は書かない。検証済みはテストが通ることが記録になり、未検証は issue で管理する。今後の開発計画も issue とマイルストーンで管理する。
- 追記はまず既存の節へ。節を増やすより、肥大化した節を各論へ切り出すことを検討する。
